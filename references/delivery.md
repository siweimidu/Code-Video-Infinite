# 交付契约

## 七项报告（缺一项就是没做完）

1. **概念**两句话
2. **带时间码的 beat sheet**（每段：时间、事件、承接物、能量高低）
3. **签名技法逐条对应**：用了哪些技法，分别在哪一段的代码/参数里实现
4. **风格选择与交接**：用了哪几种（1–2 种为宜），怎么交接的（引 blending 的哪条）
5. **技术路线**：引擎、渲染链、分辨率/fps、渲染耗时、依赖版本
6. **实测数字**：时长 / 画幅 / fps / LUFS / 真峰值 / 黑帧 / 静帧比例 / 对位漏检数 —— 来自
   `node scripts/qc.mjs measure film.mp4`，不是自述
7. **诚实的 top-3 弱点**：哪一段最可能被批评，为什么

## 报告口径

- **数字要实测**：不要写「响度大约 −14」。跑闸，贴输出。
- **不要含糊**：不写「效果不错」「比较流畅」；写「第 3 段 2.4–3.1s 承接分 0.56，警告级」。
- **不冒充**：没跑过的样片不叫复现；技术通过不等于审美达标；名称与「某某感」不保证模型身份。

## 发布与署名

- 默认**不自动公开发布**。用户要求发布时才走各引擎的发布路径（shotcraft：`engines/shotcraft/publish/upload_post.py` + `engines/shotcraft/references/publish-upload-post.md`，先 dry-run，结果 unknown 时**不重跑**，只用 `--status` 查）。
- 成片归用户所有。署名/致谢是自愿项，提一次即可，不反复推销。
- 商用授权要自己确认的两处：**Remotion 的独立许可**（shotcraft 路线）、**onetake 的 PolyForm Noncommercial**。
- 品牌名一律虚构，不用真商标；产品片里要把模板自带的 logo/文案换成用户自己的。

## A/B 隔离比较（用户要求「比较一下」时）

claude-motion 的方法值得照做：先**冻结**本 skill，用**全新上下文**生成「有 skill 版」；「无 skill 版」只给相同题目、
相同技术规格与中性导出器；两边用相同模型设置与相同自查次数；不给无 skill 版负面风格指令；不泄露另一组画面。
开发试作与正式结果分开，首次正式结果封存；效果不好如实保留，修订另开版本。
用户要求「闭卷/只给方法」时，禁用案例源码、预览与资产，并把结论限定在方法模式。
