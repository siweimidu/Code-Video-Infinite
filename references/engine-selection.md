# 引擎选择：先把需求读对，再谈风格

五个引擎解决的不是同一个问题。选错引擎，后面每个阶段都在还债。

## 一次判定，五个问题

1. **交付物是「一支片」还是「一个动作」？** 只要动作/转场/文字动效的真实源码 → **wise-motion**（它是素材供应商，不设计整片）。
2. **有没有真实产品/网页要展示？** 有，且要影视感多镜头 → **shotcraft**。有，但要 15–30 秒的节奏型发布片 → **onetake**。
3. **主体是不是具体造型（物件、角色、动物、机械、纸艺、立体场景）？** 是 → **claude-motion**（它保的是实际绘制与材质实现）。
4. **视觉语言是不是 MG 风格（扁平/线描/等轴/3D/逐帧/拼贴/液态/形变/包豪斯/Synthwave/玻璃/花字/贴纸/像素/赛博 HUD）？** 是 → **mg-motion**（15 种可检验的签名技法）。
5. **用户有没有点名工具？** 点名 Remotion → shotcraft（或直接用 Remotion）；点名 HyperFrames → 按 HyperFrames 做，别硬套本 skill 的渲染链；点名 Wise Motion → wise-motion。

三个以上都「有点像」时，选**能一次交付的最小引擎**，另外的只当素材源。

## 引擎档案

### onetake —— 节奏型短片（10–30 秒，配音功能演示可到 ~60 秒）

- **形态**：单 HTML 合成，`window.__seek(t)`；动作来自 `lib/motion.js` 的 `window.OM`；真实素材用 `record_footage.py` 录，UI 功能演示则按截图**重建**而不是录屏。
- **强项**：节奏与承接的 oracle（`verify_promo.py` 的 rhythm / burst / continuity / curves / framing 五条腿）、真实快门运动模糊、合成音效、6 套起始 look。
- **硬前提**：Python 3 + Chrome；渲染 `1080p30` 草稿，验收后才 `--final` 出 4K60。
- **明确不做**：长视频、口播、用转场剪已有素材。用户点名 HyperFrames/Remotion 就换工具。
- **代价**：4K60 逐帧渲染要时间（历史上 2,480 次捕获 ≈ 103 秒 × 8 worker），开工前给用户估算。

### shotcraft —— 电影感产品宣传片（Remotion）

- **形态**：Remotion 工程 + 真实页面捕获 + 124 张镜头配方卡 + Ink Press 完整模板 + Freesound 选音 + 动效工作台 + 剪映导出 + 社交发布。
- **三种模式，开工前必须定**：① 直接用 Ink Press 模板 ② 自主自由创作（不停下来逐步确认）③ 共同创作（按确认节点协作）。用户没选就先做一次**最小只读产品检查**，给出推荐与依据，然后问「要按这个模式继续吗」。
- **强项**：镜头卡的调校积累（含「已知坑/命门」参数，不许降档）、真实网页作为画面地基、可交剪映再改。
- **硬前提**：Node + `cd engines/shotcraft/template && npm install`；Remotion 有独立许可（公司商用需自行确认）。
- **明确不做**：纯几何抽象片（那是 mg-motion / onetake 的活）；没有页面可展示的产品它会退化成抽象片。

### claude-motion —— 造型、材质、3D 与可运行场景

- **形态**：案例辅助创作。先用 `route.mjs` 按题目检索，读候选源码与预览，选定后用 `prepare-case.mjs` / `create-*.mjs` 复制出可编辑工程，再改写主体、事件与镜头。
- **家底**：47 套源码案例、5 套可运行制作系统 + 10 支开发示例、14 个场景起点（其中 3 个实验）、20 个源码组件（含本版新增机械/程序化动物/手绘纸艺）、30 个物件模型、122 条研究清单（**未接通，不可当作可调用案例**）。
- **强项**：保留**产生视觉特征的实际实现**（造型路径、排线、印刷合成、关节、遮挡透视、运动节奏），不是只抄配色加噪点。
- **硬前提**：Node ≥ 22、Playwright Chromium、ffmpeg/ffprobe；工程目录内 `npm ci && npm run setup`。
- **明确不做**：实拍剪辑。也不能把案例原片换标题当新作。名称只代表用户想要的视觉方向，不保证模型身份或审美效果。

### mg-motion —— 15 种 MG 风格的签名技法

- **形态**：`renderAt(t)` 纯函数 + `harness/render.mjs` 逐帧渲染 + `lib/audio/` 的 103 采样配乐工具包。
- **强项**：风格 = 一组**可检验的签名技法**（可写下来才能被评审核对）；10 道机器闸（`mg-qc.mjs`）；两轮独立评审（`jury.md`）。
- **硬前提**：Chrome（Windows 上必须显式 `MG_CHROME`）、ffmpeg、Python ≥ 3.11、字体自举 `bootstrap_fonts.py`（不做这步渲染会静默卡住）。
- **明确不做**：一次上 15 种风格（同时说话 = 糊）；用 `--force` 绕过闸；把 `minMotion` 调低「通过」能量闸。
- **标尺**：上游 15 支原片终评 7.57–8.21 / 10。这是要越过的线，不是追平的线。

### wise-motion —— 动效素材供应商（462 条）

- **形态**：`match.mjs` 检索 → `show.mjs` 看预览/源码入口/依赖 → `export.mjs` 导出到目标工程。
- **强项**：真实源码 + 预览 + 参数与许可，跨 23 个分类；字幕、分镜、配色与整片组合由调用方（也就是本 skill 的流水线）自己设计。
- **边界**：**它是素材库，不是导演。** 上游把「仅在用户明确调用时使用」写进了 frontmatter；合并后仍保持这个分寸——不要因为目录大就默认用它做整片。
- **硬前提**：只要 Node.js；组件在别的工程里运行才有依赖。

## 组合配方（已验证的搭配，不是想象）

| 目标 | 组合 | 怎么接 |
|---|---|---|
| 有节奏的产品片，但缺一个具体动作 | onetake 编排 + wise-motion 取动作源码 | `find.mjs` 选条目 → `export.mjs --out-dir` → 把数值搬进 `renderAt(t)` |
| 影视感产品片，但主体是 3D 物件 | shotcraft 镜头卡 + claude-motion 物件模型 | `create-model.mjs` 出工程 → 导出序列/贴图 → 进 Remotion 当素材 |
| 要风格化 MG，但要有产品 UI 真实感 | mg-motion 风格 + shotcraft 的 PageCam 捕获 | 捕获页 → 截图进 MG 合成 → 用 mg 的签名技法驱动 |
| 发布片要配音、字幕、多语言 | onetake 多语言同源（`?lang=`）或 shotcraft 字幕轨 | 合成只保留一份，语言走参数，不做分叉 |
| 要「不像 PPT」诊断 | onetake oracle + mg 评审 | `verify_promo.py` 看 rhythm/continuity → 再派独立 subagent 按 `jury.md` 打分 |

## 反模式（会被立刻看出来）

- 想要 MG 风格却直接用 shotcraft 的镜头卡拼：卡是镜头词汇，不是风格系统。
- 在 claude-motion 里只借配色与噪点、丢掉原绘制机制：结果两支片都不像。
- 一次开 15 种 MG 风格「全用」：糊，不是超越。
- 用 wise-motion 的条目数量冒充「可整片复刻的作品数」：目录条数 ≠ 可用案例数。
- 用户点名了具体工具还硬按本 skill 的渲染链走。
