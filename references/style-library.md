# 风格库怎么用：先选族，再挑实现，最后只读两个文件

## 一、什么是「风格族」

同一个视觉规则，在多个库里各有一份实现。例如「全息 HUD」：

- `motion-showreel:hologram-hud` —— 一份 8KB 的风格文件（本质/辨识信号/运动/声音/坑）
- `claude-motion:hologram-hud` —— 一套可运行源码案例
- `mg-motion:style-22` —— mg 的第 22 号签名技法（赛博朋克 HUD/FUI）

族的清单与实现路径在 `catalog/styles.json`（82 个族，39 个跨库），人读版在 `catalog/INDEX.md` 第三节。
**选族 ≠ 选实现**：族决定「长什么样」，实现决定「用什么代码做、有什么代价」。

## 二、风格是起点，不是选择题（motion-showreel 的三条正当用法）

1. **直接用**：选一个风格，规则照着守，内容全部为主题重新设计。
2. **改造**：以一个风格为底，替换其中一两条（配色换成品牌色、运动换成步进），并在 brief 里写明改了什么。
3. **自定义**：库里没有的风格，按 `engines/garden-skills/skills/motion-showreel/references/styles/_template.md` 现写一份。

三条铁律：

- **只读你选中的那 1–2 个风格文件**，不要把整个风格库读进上下文。
- **认得出就够，不用全上**：每个风格文件列了 8–12 个辨识信号和一份「最俗的版本」。按主题挑 2–3 个信号，
  至少一个不在俗套里；同一个风格做第二支片时换一组信号。
- **换主题不换规则，也别把上一支片换文案再交一次**：故事、结构、镜头、开场结尾全部重想。

## 三、用户没指定风格时：给三个拉开差距的方向

`node scripts/pick.mjs "<需求>"` 会自动按「不同分类」给三个方向，并在你只命中一两个时补足：

| 方向 | 怎么选 | 反面 |
|---|---|---|
| **A 贴合** | 最贴近主题、品牌或素材的风格 | 三个都给「科技感」，等于没选 |
| **B 换语言** | 同样内容换一种画面语言，从**另一个分类**里选 | 只换配色 |
| **C 大胆** | 自定义、两种混搭，或结构上很大胆的讲法 | 为了大胆而牺牲可读性 |

每个方向要配一张**用真代码渲出来的关键帧**（不是参考图、不是想象稿）。三个方向不能同分类。
网页（M3）对应的是 garden 的「学校库」规则：**三个方向不许来自同一行**，否则用户看不出差别。

## 四、混搭

- **一主一辅**：主风格定全片系统（配色、字体、运动性格），辅风格只出现在一个段落或一个签名时刻。
- **按段落换媒介**：年代跨度大的主题可以每段换媒介（`mixed-media-era`），但要有贯穿的线
  （同一主角 / 同一种转场语法 / 同一首配乐）。
- 混搭时在 brief 写明**哪些规则以哪个风格为准**；冲突时以主风格为准。
- 超过 3 种风格同时在场 = 糊。15 种全上不是"驾驭"，是失控。

## 五、反 AI 陈词滥调（跨形态通用）

这一节的细节在 `engines/garden-skills/skills/web-design-engineer/SKILL.md` 的 "Avoid AI-Style Clichés" /
"Emoji Rules" / "Placeholder Philosophy" / "Aim to Stun" / "Appropriate Scale"。收敛成可执行的四条：

1. **字体不超过两套**（正文一套 + 标题一套），字号层级不超过五级。
2. **标题里不堆 emoji**；emoji ≤ 3 个（`scripts/check-web.mjs` 会数）。
3. **占位文案清零**：交付前把 lorem / 待定 / XX 换成真内容（同类脚本会抓）。
4. **"高级感"不是紫蓝渐变居中大标题**：它来自克制的层级、真实的留白、准确的细节（对齐、行高、字距）。

## 六、风格与内容的匹配

- mg-motion 的 15 种技法在 `engines/mg-motion/references/styles.md`，**末尾有「风格 × 内容 匹配」表**，选片前先查。
- motion-showreel 的 43 个风格按分组（图形与排版 / 界面与产品 / 复古与屏幕 / 3D 与材质 / 生成与抽象 /
  插画与漫画 / 手作 / 电影感）列在 `engines/garden-skills/skills/motion-showreel/references/styles/INDEX.md`，
  每行有「一句话 / 主要技术 / 常配用途 / 情绪」四列。
- 数据类内容优先 data-motion / iso / blueprint；宣言类优先 kinetic-type；产品首发优先 keynote / glass-material；
  科普优先 whiteboard；怀旧优先 retro-screen / pixel / print-ink。

## 七、把风格写进 brief（否则后面一定会跑偏）

brief 里必须有一行：

```
风格：<族 id>（<库>:<实现 id>）；主 = …，辅 = …（只用于第 X 段）
保留：<2-3 个辨识信号>；舍弃：<这个风格最俗的那个版本>
改造：<改了什么，为什么>
```

没有这一行，评审闸会判「方案不一致」。
