# 动效语法：节奏、曲线、承接、运镜

合并五个引擎后，能写下来的**可检验**规则只有这些。风格差异在这里，纪律不在这里。

## 1 · 量两个数：t80 与 smear

- **t80** = 一次移动走完 80% 距离所用的时间。它是「snap 还是 S 曲线」的唯一客观指标。
  - snap（`expoOut` 一类）t80 ≈ 0.23 × 时长 —— 先冲再停，落点硬。
  - 柔和 S 曲线（`inOutSine` / smootherstep）t80 ≈ 0.5 —— 到处都一样软，就是「每个动作都长一个样」。
- **smear** = 有没有快门拖影。超过 **~80 px/帧** 的移动没有运动模糊就会频闪成重影。
- 一支片里**不该只有一种曲线**。手搓一个 smootherstep 全局复用是最常见的塌陷方式。

onelib 里现成的数值件（纯时间函数，可任意 seek）：

```js
const w = OM.wordRise(t, 0.15);          // {op, y, s}
const c = OM.zoomThrough(t, 6.3, 7.3, card); // {matrix}
```

曲线按 t80 选，不要按名字选。可用清单见 `engines/onetake/references/motion-library.md`
（enter / carry / contact / camera / fluid 五类，共 35 个入口）与 `engines/onetake/lib/motion.js`。

## 2 · 节奏：不许按节拍器等分

- 等长镜头无论单镜多好都读成幻灯片。镜头长度要有短-长-短的呼吸。
- 参考片的切点常常**成簇**（burst）：两三个硬切挤在一起，然后一段长镜头。
- 前 **0.3 秒不许空**：hook 必须已经在动。
- 结尾定格要**有微动**（呼吸、噪点、缓慢推镜），冻住 = 省事。
- 静止是设计的一部分：参考片常有 **~34% 时间是死静**。整片不停 = 没有爆点。

## 3 · 承接：不要替换 beat，要承接它

判据（onetake oracle 的 continuity 腿）：在段落边界上，屏幕上是否有东西**活下来并可见地运动/缩放**进入下一段；
连续的得分 < 0.5 就判失败（被毙的两版 Pocket Weather 是 0.00 与 0.40，通过的是 0.75）。

- 互斥场景（`display:none` 换页）即使节奏完美也是 PPT。
- 例外：硬切爆点串、片尾卡。
- 承接的四类范式：**由主体承接**（角色落到标题上）、**由容器承接**（页面从卡片里长出来）、**由因果承接**（一次碰撞启动下一段）、**由尺度承接**（相机追着锚点，1× 与 300× 落点相同）。

## 4 · 构图与主体

- **小元素，大地面**：这类片的画幅常是 70% 留白；满屏素材是例外（一次安静的长镜）。
- **同一时刻只让一个主角动**；群组入场用 2–4 帧错峰，不要同时。
- overshoot 用 `cubic-bezier(0.34,1.56,0.64,1)` 一类有明确参数的曲线，不要「有点弹性」这种描述。
- 不要把整页缩成缩略图期待它的运动被看见：要么全幅带手，要么让页面的**一个组件**活在卡片里。
- 中文文案逐字校对：不自然的中文在评审里是 critical。

## 5 · 运镜

- 静止机位会被评价成「就缺灵动的跟踪运镜」。
- 会追的相机：**滞后、倾斜、落定**。追的是这一 beat 框住的东西，不是中心点。
- 声明 `__meta.inFrame`（哪些 id 必须在画面内）；snap 要**先 key 落点再 key 起手**，否则主体会被甩出去。
- 有 `dof` / `view` 类工具时用它做景深与推镜，不要手搓模糊冒充。

## 6 · 风格 = 可检验的签名技法

风格不是「要有科技感」，是一组能被写下来、能被评审核对的技法（mg-motion 的 15 种就是这样定义的）。
选风格后先读它的签名技法，再动手：

- `engines/mg-motion/references/styles.md`（15 种完整签名技法）
- `engines/mg-motion/references/blending.md`（2–15 种怎么混；一次上 15 种 = 糊）
- 风格 × 内容匹配表在同文件末尾，选片前先查。

## 7 · 素材语汇的两套索引

| 要什么 | 查哪里 |
|---|---|
| 镜头意图（开场、转场、数据、交互、节奏、结尾、字幕、UI 入场、特效、相机） | `node scripts/find.mjs "<意图>" --collection shot-card`，读卡全文 |
| 一个具体动作（淡入、形变、HUD 扫描、拼贴、液态……） | `node scripts/find.mjs "<动作>" --collection motion-entry` |

两套索引的差别：**镜头卡是整镜的编排配方**（含时长、能量、已知坑），**动效条目是单个动作的实现**（含参数、时长、循环、源码入口）。
